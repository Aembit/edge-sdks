# AWS Role Lambda Example

Runnable AWS Lambda example for testing the TypeScript SDK with the AWS Role Trust Provider.

This directory includes:

- `index.ts`: Lambda handler example
- `dist/index.mjs`: bundled deployment artifact generated by the build script

Run build commands from `ts/`.

## Prerequisites

- AWS Lambda function running on a Node.js `>=20` runtime
- An execution role attached to the Lambda function
- An Aembit Access Policy configured for this SDK flow

### Aembit Access Policy (Required)

Before deploying this example, configure an Aembit Access Policy that includes:

- a Client Workload that matches the Lambda execution role
- a Server Workload with a Service Endpoint (`host`, `port`) that the SDK request will target
- an AWS Role Trust Provider with an Edge SDK Client ID
- a Credential Provider that returns the requested credential type

References:

- Server Workload guide: <https://docs.aembit.io/user-guide/access-policies/server-workloads/>
- AWS Role Trust Provider guide: <https://docs.aembit.io/user-guide/access-policies/trust-providers/aws-role-trust-provider>
- AWS IAM Role auth setup: <https://docs.aembit.io/api-guide/edge/auth/aws-iam-role/>
- Get Edge SDK Client ID guide: <https://docs.aembit.io/user-guide/access-policies/trust-providers/get-edge-sdk-client-id/>

Example Server Workload configuration (for this README examples):

- Name: `Test SDK Server`
- Host: `test.example.com`
- Transport Protocol: `TCP`
- Port: `443` (TLS selected)
- Forward to Port: `443` (TLS selected; not used by SDK flow)
- Authentication Method: `No Authentication` (not used by SDK flow)

## Configure The Example

Edit [`index.ts`](./index.ts) and replace the placeholder values in `EXAMPLE_CONFIG`:

- `baseUrl`
- `clientId`
- `serverHost`
- `serverPort`
- `credentialType`
- `resourceSet` when needed
- `printCredentialJson` if you want the full credential in the Lambda response

The deployed Lambda runtime should provide `AWS_REGION` automatically.
For local testing outside Lambda, set `AWS_REGION` or `AWS_DEFAULT_REGION`.

## Build The Lambda Artifact

Run from `ts/`:

```bash
npm run build:example:aws-role-lambda
```

To create a zip artifact for upload:

```bash
npm run example:aws-role-lambda:zip
```

This produces:

- `examples/aws-role-lambda/dist/index.mjs`
- `examples/aws-role-lambda/dist/aws-role-lambda.zip`

## Deploy To Lambda

Upload `examples/aws-role-lambda/dist/aws-role-lambda.zip` to your Lambda function.

Recommended Lambda settings:

- Runtime: `Node.js 20.x` or newer
- Handler: `index.handler`

## Observe The Output

Invoke the Lambda function and inspect the returned response payload.

Recommended path:

- use the Lambda console `Test` feature and view the response JSON

You can also invoke with the AWS CLI:

```bash
aws lambda invoke \
  --function-name your-function-name \
  --cli-binary-format raw-in-base64-out \
  --payload '{}' \
  response.json

cat response.json
```

By default, the handler returns safe metadata only:

```json
{
  "authenticated": true,
  "trustProviderId": "aws-role",
  "credentialType": "ApiKey",
  "credentialExpiresAt": "2026-03-10T19:19:09.2559713Z",
  "dataKeys": ["apiKey"]
}
```

If `printCredentialJson` is set to `true` in `EXAMPLE_CONFIG`, the response includes the full credential payload instead:

```json
{
  "authenticated": true,
  "trustProviderId": "aws-role",
  "credentialType": "ApiKey",
  "credentialExpiresAt": "2026-03-10T19:19:09.2559713Z",
  "credential": {
    "credentialType": "ApiKey",
    "expiresAt": "2026-03-10T19:19:09.2559713Z",
    "data": {
      "apiKey": "sekretk3y!"
    }
  }
}
```

The example returns the credential information in the Lambda response.
It does not log the credential payload by default.

## Troubleshooting

### Missing AWS region

If the function fails with `Missing AWS region. Set AWS_REGION or AWS_DEFAULT_REGION.`, verify:

- the function is running on Lambda, or
- your local test environment exports `AWS_REGION` or `AWS_DEFAULT_REGION`

### `401` on `/credentials`

Verify that `baseUrl` in `EXAMPLE_CONFIG` is the final regional Edge host and does not redirect.

Example:

- `https://<tenant>.ec.<region>.aembit.io`

### `200` with `credentialType: "Unknown"` and empty `data`

This indicates that the request reached Edge, but did not match the expected access policy or service request shape.

Verify:

- `serverHost` and `serverPort`
- `credentialType`
- Lambda execution role mapping in the Client Workload
- `resourceSet` if your tenant flow uses it

## Security Note

Do not use real secrets in shared logs or screenshots.
Set `printCredentialJson` to `true` only for controlled testing.
